# EverShell 需求文档

> 状态：需求已确认（2026-10-17），技术架构为建议方案，需在 M0 技术验证后定稿。

## 1. 背景与目标

- 复刻 FinalShell，先自用，以后可能开放给别人用。
- FinalShell 很久没更新，云同步依赖它的官方服务。一旦停服，同步数据就没了。
- 目标：
  1. **数据在自己手里**：同步服务部署在自己的 VPS 或自己的 Cloudflare 账号上，随时能导出、迁移。
  2. **全平台**：macOS、Windows、网页、iOS、Android。
  3. **界面现代**：保留 FinalShell 用惯的布局，整体视觉翻新。

## 2. 平台与阶段

| 阶段 | 平台 | 说明 |
|---|---|---|
| 本阶段 | macOS → 网页 → Windows | 先在 Mac 上做到能日常用，再上网页版，最后做 Windows |
| 后续 | iOS、Android | 有 Apple 开发者账号，iOS 用 TestFlight 安装 |

## 3. 功能需求

### 3.1 核心功能（P0，复刻 FinalShell）

- **SSH 终端**：多标签、分屏、配色主题、字体设置、关键词高亮；支持密码、私钥、键盘交互（二次验证）三种认证方式。
- **SFTP 文件管理**：放在终端下方；支持拖拽上传下载、传输队列、双击在线编辑、修改权限，文件目录可以跟随终端当前目录。
- **服务器监控**：放在左侧，实时显示 CPU、内存、交换分区、网速、磁盘和进程列表。服务器上**不装任何 agent**，跟 FinalShell 一样直接通过 SSH 执行命令采集数据。
- **快捷命令**：收藏命令片段、查看历史命令、一键发送到当前终端。
  - **不自动回车（2026-10-25 所有者定）**：每条命令可以勾「不自动回车」，点了只把文字放进终端，照 FinalShell。
  - **导入别的软件的快捷命令（2026-10-25 所有者定，方案 A）**：入口在命令页，流程和导入连接一样（选来源 → 选文件 → 预览 → 完成）。这次支持 FinalShell、SecureCRT 按钮栏（这两家能一键导入）和 Electerm 的导出文件；Xshell、Tabby、iTerm2 等先不做，原因和格式依据见 [docs/specs/command-import.md](specs/command-import.md)。

### 3.2 进阶功能（P1）

- **端口转发 / 跳板机**：本地转发、远程转发、动态转发（SOCKS）；支持跳板机（ProxyJump）和 HTTP / SOCKS 代理。
- **批量执行**：一条命令同时发到多台服务器，分别查看每台的输出。
- **远程桌面**：RDP（Windows）和 VNC。

### 3.3 新增改进（P1–P2，FinalShell 没有的功能）

- **AI 助手**：用自然语言描述生成命令、解释报错、总结日志；API Key 用户自己配置。
- **智能补全**：根据历史命令和当前目录给出补全建议（类似 Fish、Warp）。
- **会话日志**：自动保存终端输出，可全文搜索、可回放。
- **密钥管理**：统一生成和导入 SSH 密钥，一键把公钥部署到服务器。其中“私钥库”（导入一次、多台服务器共用，照 FinalShell）所有者 2026-10-25 要求提前到 M1 做，规格见 [docs/specs/key-library.md](specs/key-library.md)；生成密钥、部署公钥仍在 M5。

### 3.4 导入现有连接

由用户手动触发：打开导入窗口时才去各软件的默认位置找配置，平时不扫描：

- **FinalShell**：从配置目录导入连接，分组、密码、私钥一起迁移（FinalShell 的密码加密算法是公开的，可以解密）。
- **~/.ssh/config**：导入其中的 Host 条目。
- **其他工具**：Xshell、Termius、MobaXterm 等，按各自的导出格式逐个支持。

**已实现（2026-10-17）**：入口在连接管理器的工具栏和 ≡ 菜单。导入流程是“选来源 → 选文件 → 预览勾选 → 完成”，界面里写明了各来源的配置文件在 Mac 和 Windows 上的位置。

| 来源 | 导入内容 | 密码 |
|---|---|---|
| FinalShell | conn 目录下的连接和文件夹层级 | 解密后存进保险箱（网页端不存） |
| Xshell | Sessions 目录下的 .xsh，子目录作为文件夹 | 不导入（加密和 Windows 账户绑定） |
| MobaXterm | .mxtsessions 或 MobaXterm.ini 里的 SSH 会话 | 不导入 |
| PuTTY | 注册表导出的 .reg 里的 SSH 会话 | 不导入 |
| SecureCRT | Sessions 目录下的 .ini，子目录作为文件夹 | 不导入 |
| OpenSSH config | Host 条目（通配符条目跳过，Include 不展开） | 无 |
| EverShell 导出文件 | 完整的文件夹和连接设置 | 导出时就不含密码 |

- **一键导入（2026-10-23）**：桌面端打开导入窗口时，去 FinalShell、SecureCRT、PuTTY 和 `~/.ssh/config` 的默认位置找配置，找到的来源后面标「已找到 N 个连接」并默认选中，点「一键导入」跳过选文件、直接预览；没找到的照旧手动选。网页端读不了本机文件，没有这个功能。规格见 [docs/specs/one-click-import.md](specs/one-click-import.md)。
- 不导入密码的来源，第一次连接时再输入。
- 重名的连接可以选跳过、覆盖或两份都保留。
- 「导出连接」把连接存成 EverShell 自己的文件，不含密码和私钥；桌面端存进“下载”目录，网页端由浏览器下载。
- Termius 暂不支持（没有找到可直接读取的本地配置格式）。
- 解析代码在 `packages/ui/src/core/importers/`，单元测试只用编造的样例文件。

### 3.5 密码和私钥的保存（2026-10-18 定）

- **保险箱**：保存的密码、私钥、私钥密码都加密后放进软件自己的一个文件（保险箱）。加密用一把随机生成的**保险箱钥匙**（XChaCha20-Poly1305），每条单独加密。
- **钥匙放在系统钥匙串里**，钥匙串里只有这一条。正式版签名后，存和读都不弹框，用户无感。
  - 比 FinalShell 的做法（固定的公开钥匙，拿到配置文件就能解开）多防住：其他软件悄悄读取、文件被备份或拷走、电脑丢失且没开磁盘加密。
  - 防不住知道电脑密码的人，要防得开 Touch ID（见下）。
- **第一次使用不要求设主密码**。只有开启云同步时才要求设，见第 4 节。
- **Touch ID 由用户手动开启**（以后做）：保险箱钥匙改由 Mac 的指纹芯片锁住，只认指纹，电脑密码代替不了。开启时必须同时设主密码作后备（新加指纹会让芯片钥匙作废），并删掉钥匙串里那份钥匙。开启时要提示：这台 Mac 上登记的所有指纹都能解锁。
- 各平台放钥匙的地方：Mac 钥匙串，Windows 凭据管理器，网页端没有钥匙串，到 M3 再定（主密码或不存）。
- 钥匙串里找不到钥匙、或者钥匙对不上保险箱时，旧保险箱改名留作备份，换一个新的，用户下次连接时重新输密码。
- 开发期以前是每条机密单独存一条钥匙串，读到时自动搬进保险箱并删掉原条目。正式发布前可以删掉这段迁移代码。
- 实现：加密在 `crates/vault`（能编成 WASM），桌面端存取在 `apps/desktop/src-tauri/src/secrets.rs`，保险箱文件是应用数据目录下的 `vault.json`。

### 3.6 本阶段不做

- Telnet / 串口
- iOS / Android 客户端
- FinalShell 的网络加速等付费附加功能

## 4. 云同步

- **两种后端都支持，客户端里可以切换**：
  - **自建**：一个 Docker 镜像部署到自己的 VPS。
  - **Cloudflare**：Workers + D1 / R2，部署在用户自己的 Cloudflare 账号下。
- **端到端加密**：
  - 数据用主密码派生出的密钥在本地加密后再上传，服务器只存密文（建议算法：Argon2id + XChaCha20-Poly1305）。
  - 主密码在开启同步时才设置。设置后用它把保险箱钥匙（见 3.5）另锁一份随同步上传，已存的密码不用重新加密。改主密码也只是换这把锁。
  - 新设备输入一次主密码解锁，取出保险箱钥匙存进本机钥匙串，之后不再询问（开了 Touch ID 就用指纹）。
  - 两台设备之前各自单机用过：后加入同步的那台把自己的条目用同步的保险箱钥匙重新加密后合并。
  - 主密码丢了无法找回。建议注册时生成一份**恢复码**，让用户自己保存（待确认）。
- **按多账号设计**：账号体系、数据隔离、存储配额从第一版就做进去。以后可以让不想自建的人用你的服务；数据是端到端加密的，你作为运营者也看不到他们的内容。
- **离线优先**：每台设备本地都有完整副本，断网照常用，联网后自动合并（逐条记录比较版本号，删除用墓碑标记）。
- **随时导出**：可以导出加密备份文件，恢复时不依赖任何服务器。

## 5. 网页版

- **要求完整功能**：终端、SFTP、监控、远程桌面都要能在网页上用。
- **限制**：浏览器没法直接建立 TCP 连接，必须经过一个中转服务。
- **建议方案**：
  - SSH / RDP 协议在浏览器里运行（Rust 内核编译成 WASM），中转服务只做 WebSocket ↔ TCP 的字节转发。
  - 好处一：自建服务和 Cloudflare Workers 都能当中转。
  - 好处二：密码和私钥不会经过中转。
- **中转必须鉴权**：登录后才能使用，避免被别人当成开放代理滥用。
- **待验证的风险**（M0 阶段做验证）：
  - russh 能否编译成 WASM。如果不行，退路是让自建中转直接跑 SSH，但这样 Cloudflare 就当不了中转。
  - IronRDP 网页端对中转服务有特殊要求（RDCleanPath）。
  - Cloudflare Workers 的 TCP 连接有限制：连不了 Cloudflare 自家的 IP，个别端口被封。

## 7. 技术架构（建议）

- **客户端外壳**：Tauri 2（桌面端，以后也能打包 iOS / Android）。
- **界面**：React + TypeScript；终端组件用 xterm.js。桌面端和网页版共用同一套界面。
- **Rust 内核**：SSH / SFTP（russh）、端口转发、监控采集、加密、同步引擎。同一份代码在桌面端原生运行，在网页端编译成 WASM 运行。
- **远程桌面**：RDP 用 IronRDP（Rust），VNC 用 noVNC 或 Rust 实现。
- **同步与中转服务**：TypeScript + Hono，一套代码两种部署：
  - Docker：Node / Bun + SQLite
  - Cloudflare：Workers + D1 / R2
