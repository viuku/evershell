# 安全

> **管什么**：要保护什么、防谁（威胁模型）；写代码的红线；加密为什么这么选；依赖和 russh 的跟进；漏洞报告渠道。
> **什么时候更新**：加了会碰机密或网络的功能、换了加密方案、出了安全问题；每个里程碑结束复核一次威胁模型。
> **上次复核**：2026-10-18

EverShell 保管的是能登录别人服务器的东西，安全排在所有原则的第一位（[product.md](product.md#产品原则)）。依据见调研 [附录 C 第 1 节](../research/2026-10-appendix-c-ssh-client-concerns.md) 和 [附录 A 第 3.6 节](../research/2026-10-appendix-a-peer-projects.md)。

## 要保护什么

| 资产 | 有多要紧 | 现在放哪 |
|---|---|---|
| 服务器密码、私钥、私钥口令 | 最高，直接能登录服务器 | 保险箱 `vault.json`，加密 |
| 保险箱钥匙 | 等于全部机密 | macOS 钥匙串，只这一条 |
| 主密码和它派生的钥匙（M2） | 等于全部同步数据 | 只在内存里 |
| 连接清单（主机、端口、用户名、分组） | 高，是攻击目标的地图 | 本机存储，明文 |
| 主机密钥记录（known_hosts） | 被改了就等于放行中间人 | 桌面端：保险箱条目 `known_hosts`（加密，改不了）；网页端：浏览器本地存储 `evershell.knownHosts` |
| 快捷命令、历史命令、以后的会话日志 | 常夹带密码和令牌 | 本机存储 |
| 中转令牌、同步账号凭据 | 能冒用中转或下载密文 | 中转令牌现在在网址里（M0） |
| 发布签名证书、以后的更新签名私钥 | 能给所有用户推恶意版本 | 开发机钥匙串；以后放 CI 受保护环境 |

## 防谁

| 攻击者 | 能做什么 | 现在的态度 |
|---|---|---|
| **恶意或被攻破的 SSH 服务器** | 发终端转义序列（读剪贴板、伪造链接）、发畸形数据打崩客户端、给 SFTP 返回恶意文件名、借 agent 转发用你的私钥 | **最常见**：同类客户端 32 个公告里大多是这种。服务器给的一切都当不可信输入 |
| 网络中间人 | 首次连接时冒充服务器、降级攻击 | 主机密钥校验（2026-10-18 起）：没见过的先问用户，变了硬拦截。挡不住“第一次连接就被冒充”，这是首次信任的固有弱点，要用户自己核对指纹 |
| 恶意的导入文件或同步数据 | 在配置里藏可执行字段、篡改数据 | 只导入白名单字段；同步把服务器当不可信存储 |
| 同机的恶意软件 | 读应用数据、读剪贴板、冒充本应用读钥匙串 | 保险箱加密 + 钥匙在钥匙串，挡住“悄悄读文件”；挡不住已经拿到用户权限并被用户允许的程序 |
| 电脑丢失、备份泄露 | 离线读磁盘、拿到配置目录 | 保险箱加密；钥匙不在备份文件里 |
| 被攻破的同步服务器（M2） | 读、改、删、回滚密文 | 端到端加密 + 完整性校验，服务器只存密文 |
| 被滥用的中转（M3） | 当开放代理、扫内网 | 鉴权 + 默认禁内网地址（M3 前做） |
| 供应链投毒 | npm / crates 包、GitHub Actions | 依赖审计、固定版本（见下） |
| WebView 里的恶意脚本 | 通过 IPC 调 Rust 命令 | CSP（2026-10-18 起开启，禁远程脚本和 eval）+ capabilities 最小化 |

需求文档 3.5 写了保险箱“防得住什么、防不住什么”，以那里为准。

## 红线

写代码时不能碰的：

1. **机密只进保险箱。** 密码、私钥、口令不写进连接清单、设置、日志、错误提示、导出文件。
2. **机密不进日志。** 带机密字段的类型不派生 `Debug`（或者手写打码的版本，像 `VaultKey(..)`）；终端数据、按键、文件内容永不进日志；服务器返回的字符串写日志前转义。
3. **服务器给的一切都是不可信输入**：
   - SFTP 文件名拼本机路径时，在 Rust 端规范化，并确认结果还在目标目录里（防路径穿越）；
   - 远程路径、文件名不拼进 shell 命令；非拼不可时统一走一个转义函数；
   - 终端里的链接只自动处理 http / https，其他协议要用户确认；
   - 剪贴板转义序列（OSC 52）只允许写、不允许读，或者每次问用户。
4. **导入只认白名单字段**，导入的快捷命令、启动命令这类“会执行的东西”要用户确认。
5. **不自己发明加密**，只用成熟库（RustCrypto、ring），方案按下面“加密选型”。
6. **Tauri 权限最小化**：capabilities 只开用到的；不加“执行任意命令”“读任意文件”这类通用命令；以后注册 `ssh://`、`evershell://` 链接时，参数要白名单，绝不接受命令类字段。
7. **不放宽主机密钥校验**：密钥变了只给「取消」和「我已核实，更新密钥」，没有“只接受本次”，更没有“继续”的大按钮。内核的 `HostKeyCheck::AcceptAny` 只给连本机测试服务器的测试用，正式连接一律走 `KnownHosts`。

## 加密选型

| 用在哪 | 选了什么 | 为什么 |
|---|---|---|
| 保险箱里每条机密 | XChaCha20-Poly1305，随机 24 字节 nonce，附加数据带条目编号和格式版本 | 192 位 nonce 随机生成不会撞；AES-GCM 随机 nonce 同一把钥匙只能安全加密约 2^32 次（附录 C 1.3） |
| 保险箱钥匙 | 随机生成，存系统钥匙串 | 用户无感；钥匙串只有一条，最多问一次 |
| 同步（M2，设计时再定） | 主密码用 Argon2id 派生，派生结果拆成“加密钥匙”和“服务器认证凭据”两半；数据钥匙随机生成，主密码只用来锁它；密文带版本号 | 照 Standard Notes 004 的设计，算法和 EverShell 完全一样；改主密码不用重新加密全部数据（附录 C 1.3、5.4） |
| 加密导出（以后） | Argon2id + XChaCha20-Poly1305，参数存在文件里 | 和同步一致；恢复时不依赖任何服务器 |

Argon2id 参数参考 RFC 9106 和 OWASP（附录 C 1.3 列了 Bitwarden、Standard Notes 的实际取值）。注意 Cloudflare 免费计划每个请求只有 10ms CPU，重的派生只能放客户端（附录 B 第 10 节）。

## 依赖和 russh

- **russh 跟进**：russh 2026 年发了约 20 条安全公告，好几条是恶意服务器能打客户端。订阅它的安全公告，出安全版本后一周内重打补丁升级（升级步骤见 [vendor/README.md](../../vendor/README.md)）。把两处补丁提给上游、早日去掉 vendor，是降低维护成本最有效的一步。
- **Tauri 跟进**：同样订阅安全公告，出安全版本后跟进。
- **其他依赖**：加之前过 [architecture.md](architecture.md#加依赖的门槛) 的门槛。建 CI 时加 cargo-deny（漏洞 + 协议）、npm audit、Dependabot（见 [quality.md](quality.md#还没建的)）。
- **前端打包不能带进私钥**：vite 的 `envPrefix` 现在是 `VITE_` 和 `TAURI_ENV_*`，不包含更新私钥的变量名。改 vite 配置时保持这一点（附录 B 第 4 节）。

## 已知缺口（2026-10-18）

修好一条删一条。2026-10-18 已经修好、从这里删掉的：主机密钥不校验、不发心跳、SFTP 上传截断原文件、终端没有回压、CSP 没开。

- **主机密钥：证书机构（`@cert-authority`）的记录不支持**，读到这种行会跳过；服务器出示证书时，只按证书里的公钥校验，不验证书本身。
- **CSP 放行了内联样式**（`style-src 'unsafe-inline'`）：xterm.js 要在运行时插入样式，不放行终端就没颜色。脚本仍然禁内联和 eval（原因见 [pitfalls.md](pitfalls.md#开了-csp-以后-xtermjs-的样式会被拦2026-10-18)）。
- **机密在前端经过**：三个平台都是前端从 `SecretStore` 取出密码放进连接参数。以后改成前端只传连接编号、后端自己取，要三个后端一起改，先写规格（[process.md](process.md#3-规格)）。
- **中转令牌放在网址里、目标地址不限**（M0 已知，M3 前改）。
