# 私钥库：导入一次，多台服务器共用

> 2026-10-25。所有者要求“已经导入的密钥其他服务器要用可以不用重复导入，参考 FinalShell 的做法”，选了设计稿的方案 A，并同意把已经存过的私钥自动搬进私钥库。

## 问题

私钥现在跟着服务器存：保险箱里每台服务器一条 `<服务器 id>.privateKey`（口令是 `<服务器 id>.passphrase`）。同一把私钥给三台服务器用，就要导入三次，口令也要输三次；换私钥时要一台台改。

FinalShell 的做法：私钥统一放在一个列表里（名称、类型、长度），编辑连接时点「浏览…」从列表里选，列表里能导入、编辑、删除。

需求文档把“密钥管理”排在 M5（生成密钥、一键部署公钥）。这次只做其中“导入一次、多处使用”，生成和部署留在 M5。

## 界面（方案 A）

设计稿：https://claude.ai/artifact/Sc2TUsbjVw2f8uRvpptcrD 。

- 编辑连接的认证方式只剩「密码」「公钥」两种，去掉一直没做的「密钥库」。选「公钥」时，「私钥」一栏显示选中的那把（如「dmit · RSA 2048」），旁边「选择…」打开「选择私钥」；下面一行小字说明私钥和口令存在本机、别的服务器也能选。服务器自己不再有口令一栏，口令跟着私钥存。
- 「选择私钥」：表格列出名称、类型、长度、用在几台服务器；右边「导入…」「改名…」「删除…」；双击一行或选中后点「确定」就选用。比 FinalShell 多一列「用在」，删的时候知道会影响谁。
- 「导入私钥」：选文件（桌面端走 `pickPrivateKeyFile`，云盘里的文件也能读）或粘贴；名称默认用文件名；口令没有就留空。选好后显示认出来的类型和长度；是公钥、设了口令没填、口令不对、已经导入过、认不出来，都在这里直接说，导入按钮不放行。
- 改名用通用的输入框；删除先确认，有服务器在用时写明几台，删除后这些服务器的私钥一栏变回「未选择」，连接时会请用户选。
- 连接时：服务器选了私钥就直接用；没选或者选的那把被删了，照旧弹框让用户选文件或粘贴，勾「记住私钥」就放进私钥库（已经在库里的同一把就直接用那条）并记到这台服务器上。
- 网页端不保存私钥（保险箱不可用），照旧：编辑连接里选文件只用于测试，每次连接时选择。

## 数据

### 私钥库清单：`evershell.keys.v1`（新）

经 `core/storage.ts` 存，各窗口同步。不含机密，只有显示和查重用的信息：

```json
{
  "version": 1,
  "keys": [
    {
      "id": "key_m2x9k3ab12cd",
      "name": "dmit",
      "algorithm": "RSA",
      "bits": 2048,
      "fingerprint": "SHA256:47DEQpj8HBSa+/TImW+5JCeuQeRkm5NMpJWZG3hSuFU",
      "createdAt": 1792940000000,
      "updatedAt": 1792940000000,
      "deletedAt": null
    }
  ],
  "migratedServerKeys": true
}
```

- 三个同步字段照 [data.md](../handbook/data.md#记录的字段约定)；删除打墓碑，界面上隐藏。
- `fingerprint` 是公钥指纹（`ssh-keygen -lf` 的那串），不是机密，用来认“同一把私钥”。
- `migratedServerKeys`：旧数据搬完了，以后启动不再检查。

### 私钥内容：保险箱

- `<私钥 id>.privateKey`：私钥原文；`<私钥 id>.passphrase`：口令，私钥没设口令就没有这条。
- 私钥 id 以 `key_` 开头，服务器 id 以 `srv_` 开头，和服务器的 `<服务器 id>.password` 不会撞。
- 删除私钥时这两条立刻从保险箱删掉，清单里只留墓碑。

### 服务器记录：加 `keyId`

- `ServerRecord.keyId: string | null`：认证方式是「公钥」时选的哪把私钥。`keyLabel` 保留：从别的软件导入、还没选私钥的服务器，用它在连接弹框里提示原来用的私钥文件名，搬家时也用它给私钥起名。
- `auth` 只剩 `password` / `key`。读到旧的 `keychain` 当成 `key`。
- 连接清单 `evershell.hosts.v1` 的格式版本不变：只多了一个可选字段，旧版本读的时候原样保留（`normalize` 用的是展开再覆盖），不会弄丢；旧版本连这类服务器会找不到私钥、弹框让用户选，不会坏数据。
- 导出（`evershell-connections`）不带 `keyId`：别的电脑上没有这把私钥，带了也没用，和不导出密码一样。

### 旧数据搬家

主窗口启动后（保险箱可用、能认私钥时）跑一次，代码在 `core/key-library.ts` 的 `migrateServerKeys`：

1. 先把连接清单原样备份到 `evershell.hosts.v1.before-key-library`（只备份一次）。
2. 逐台看认证方式是公钥、还没有 `keyId` 的服务器：保险箱里有 `<服务器 id>.privateKey` 就读出私钥和口令，认出类型、长度、指纹。
3. 指纹和库里已有的（含这次刚搬的）一样就共用那条；一样的私钥认不出来时按原文比。否则新建一条：名称用 `keyLabel`（去掉“已粘贴私钥”这类占位），没有就用服务器名；重名时后面加「 (2)」。
4. 写进保险箱的新条目读回来核对一致后，才给服务器记上 `keyId`，再删掉旧的两条。中途失败（保险箱写不进、读回来不一致）就停下，旧条目不动，`migratedServerKeys` 不设，下次启动再试。
5. 认不出来的私钥（比如格式太老）也照样搬，类型和长度显示「未知」，指纹为空。
6. 全部搬完设 `migratedServerKeys: true`。`keychain` 的服务器顺手改成 `key`。

## 内核：认私钥

`crates/ssh-core` 加 `inspect_private_key(text, passphrase) -> Result<KeyInfo, KeyProblem>`，原生和 WASM 都能编：

- `KeyInfo { algorithm, bits, fingerprint, encrypted }`：算法名（RSA、ED25519、ECDSA、DSA，其他照原名）、长度（RSA/DSA 按模数位数，ED25519 是 256，ECDSA 按曲线 256/384/521）、SHA256 指纹、有没有设口令。
- 解析用 russh 的 `decode_secret_key`，和真正连接时同一套，支持 OpenSSH、PEM（RSA / EC / PKCS#8，含加密的）、PuTTY。
- `KeyProblem`（文案直接给用户看）：公钥（一般是 .pub）、设了口令没填、口令不对、认不出来。
- 私钥没设口令、却填了口令：照常认出，`encrypted` 为 false，界面不存这个口令。

桌面端命令 `key_inspect`；接口 `SshBackend.inspectPrivateKey?`（读不懂抛错）。网页端不保存私钥，用不到私钥库，先不接；`?mock` 的假后端按文件头给个假结果。

## 放弃的方案

- **方案 B（下拉框）**：所有者选了 A。
- **私钥和清单都放保险箱**：清单要在各窗口同步、以后要云同步，和连接清单放一起管理更一致；清单里没有机密。
- **连接清单升到 v2**：只加可选字段，旧版本不会弄丢，升版本反而让旧调试版完全读不了连接清单。

## 对其他平台的影响

- 网页端：没有私钥库，行为不变。以后网页端要存私钥（M3 之后，保险箱方案定了再说）时，`inspectPrivateKey` 接 WASM 版的同一个函数。
- Windows、手机：界面和数据逻辑都在 `packages/ui` 和内核里，跟着用。
- 同步（M2）：私钥清单带了同步字段；私钥内容同步要走主密码加密，到时候和密码一起设计。

## 怎么测

- 内核单元测试：OpenSSH 无口令 / 有口令 / 口令错、PEM RSA、公钥、乱七八糟的文本；长度和指纹对得上 `ssh-keygen` 的结果。
- 界面单元测试（`core/key-library.ts`）：导入查重、改名、删除时清掉服务器的 `keyId` 和保险箱条目；搬家：同一把私钥两台服务器只建一条、名称取 `keyLabel`、重名加序号、写入失败时不动旧条目、搬完不再跑；`resolveAuth` 用库里的私钥、选的私钥被删了就弹框、勾“记住”放进库并共用已有的。
- 网页版 `?mock`：选择、导入、改名、删除走一遍，深浅色各看一遍。
- 桌面端：`scripts/check.sh core desktop`。真实私钥（OneDrive 里的）导入、搬家后连接，请所有者试。
