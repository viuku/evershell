# 快捷命令的分类清单

> 2026-10-23。所有者已看过设计稿并同意加这份存储，已做。

## 问题

底栏的「快捷命令」改成 FinalShell 那样的「命令」页：上面一排分类，能新建、改名、删除，空分类也要留着。原来分类只是每条命令上的 `group` 字段（分类名），没有命令的分类就不存在，顺序也只能按命令出现的先后。

## 方案

另存一份分类清单，命令记录不动。

- **新键** `evershell.snippet-groups.v1`：分类名的数组，顺序就是显示顺序，例如 `["常用","Docker","部署"]`。读的时候丢掉不是字符串的、空的、重复的。
- **命令记录**（`evershell.snippets.v1`）格式不变，`group` 还是分类名。缺 `group` 或为空的记录读进来时归到「默认分类」。
- **显示哪些分类**：清单里的按清单顺序，命令里引用到、清单里没有的按出现顺序补在后面（`listGroups`）。
- **改名**：清单里原位替换，引用它的命令一起改名，这些命令的 `updatedAt` 更新。新名字不能为空、不能和别的分类重名。
- **删除**：清单里去掉，里面的命令一起删（真删，快捷命令还没有墓碑，见 [data.md](../handbook/data.md#记录的字段约定)）。有命令的分类删除前确认。
- **新建命令**：没指定分类就放进第一个分类；一个分类都没有时放进「默认分类」，并把它加进清单。
- 每次增删改都把合并后的整份清单写回去，老数据里只靠命令引用出来的分类从此进了清单，删光里面的命令分类也还在。

代码在 `packages/ui/src/core/snippets-store.ts`：`with…` 开头的是纯函数（给定清单和命令算出新的一份），`addGroup` / `renameGroup` / `removeGroup` / `addSnippet` 等负责读写存储。

放弃的方案：给命令记录加分类编号、分类做成带 id 的记录。那样改名不用动命令，但要改命令的格式、写迁移；现在只有本机数据，按名字引用够用，留给 M2 设计同步时再定。

## 老数据

不用迁移。老用户没有新键，打开时分类从命令里合并出来，和以前看到的一样；第一次改动后写下新键。降级回老版本时新键被忽略，空分类看不到，命令都还在。

## 导出和以后的同步

- 连接导出（`evershell-connections`）不含快捷命令，不受影响。
- 分类清单没有 `id`、`updatedAt`、`deletedAt`，不符合 [data.md](../handbook/data.md#记录的字段约定) 对要同步的数据的约定。M2 设计同步时和快捷命令缺墓碑一起处理：可以把整份清单当一条记录、带一个更新时间，也可以改成带 id 的分类记录（属于格式变化，要升 v2 并迁移）。按名字引用意味着改名要同时改清单和多条命令，同步时要当成一次改动处理，不然另一台设备可能只收到一半。
