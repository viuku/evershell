# 双击远程文件直接编辑

> 2026-10-23。所有者看过设计稿后定了：编辑器单独开一个窗口（像 FinalShell）、用成熟的开源编辑器（CodeMirror 6，MIT 协议，编辑器和语法加起来约 0.6 MB，按需加载）。已做完；网页版 `?mock` 验过，桌面端的独立窗口等所有者试。

## 问题

文件区双击文件现在什么也不做，想改服务器上的配置只能下载、用别的软件改、再上传。FinalShell 双击就打开它自带的编辑器，保存时自动传回服务器。所有者要同样的体验：除非点「下载」，否则不把文件落到电脑上。

## 方案

设计稿：https://claude.ai/artifact/TwkhWsTaeeXyQYcM6ccNgM

### 界面

- 文件区双击文件、或右键「编辑」：读进内存，在编辑窗口里开一个标签。已经开着就切过去。右键菜单「编辑」排第一，「下载到本机」第二；工具栏的「下载」照旧。
- 打不开的两种情况弹提示，按钮是「下载到本机」「取消」：超过 5 MB；内容不是 UTF-8 文本（前 8 KB 里有 0 字节，或者整体不能按 UTF-8 解码）。目录、链接到目录的符号链接双击照旧是进入目录。
- 编辑窗口：顶上一排文件标签（没保存的标签上是圆点，有修改时关闭会问），下面一行「保存」「重新载入」「查找」、远程路径、状态（未保存 / 正在上传… / 几点几分已保存到服务器 / 和服务器上一致 / 保存失败的原因），底下一行编码、换行符、光标位置、语法类型。⌘S 保存，⌘F 查找。语法颜色按文件名猜：nginx、shell、yaml、json、toml、ini、Dockerfile、Python、JavaScript、XML/HTML、CSS，猜不到就是纯文本。
- 保存前先看服务器上的文件变没变（修改时间或大小和打开时不一样）：变了就问「服务器上的文件已被改过」，可以「仍然保存」「重新载入」「取消」。
- 保存走现有的上传（先写临时文件再替换、保留权限和所有者，见 `crates/ssh-core/src/sftp.rs` 的 `upload`），也进传输列表。
- 进度（所有者 2026-10-23 要的，网络慢时不至于以为没点上）：双击打开时，文件区那一行的大小一栏显示「打开中 45%」，底下一条进度线；保存、重新载入时，编辑器状态前面有进度条和百分比。还没开始传（先查大小、比对版本）时进度条来回走。打开和保存都进传输列表。
- 会话断开时保存会失败，提示原因；重连后同一个会话标签再保存就行。

### 窗口

桌面端编辑器是另一个原生窗口（标签 `editor`），同一时刻只有一个，里面放多个文件标签。网页端（包括 `?mock` 预览）没有原生窗口，编辑器在主窗口里浮着，界面组件是同一个。

文件读写全在主窗口做：会话、传输列表、断线重连都在主窗口里，编辑窗口只管显示和改文字。两边靠消息说话：

| 方向 | 消息 | 内容 |
|---|---|---|
| 主 → 编辑 | `open` | 文档编号、会话编号、服务器名、远程路径、文字、换行符 |
| 主 → 编辑 | `progress` | 保存（上传）或重新载入（下载）的进度，百分比变了才发 |
| 主 → 编辑 | `saved` / `failed` / `conflict` / `reloaded` | 对应某个文档的保存结果、失败原因、冲突时服务器上的修改时间、重新载入的文字 |
| 编辑 → 主 | `ready` | 编辑窗口刚打开，主窗口把还没送达的 `open` 补发 |
| 编辑 → 主 | `save` | 文档编号、文字、`force`（冲突后「仍然保存」） |
| 编辑 → 主 | `reload` / `close` | 文档编号 |

主窗口只记“文档编号 → 会话、路径、打开时的修改时间和大小”，文字只在编辑窗口里。

关窗口：编辑窗口有没保存的文件时，点关闭先问；主窗口关闭时如果编辑窗口还有没保存的，主窗口先不关，切到编辑窗口问「保存」「不保存」「取消」，处理完再一起关。编辑窗口用命令 `editor_set_dirty` 告诉 Rust 有没有没保存的。

### 接口

`SshSession`（`packages/ui/src/types.ts`）加两个方法：

- `stat(path)`：返回 `FileEntry`（跟着符号链接）。打开前取大小和修改时间，保存前比对。
- `readFile(path, maxBytes, onProgress?)`：整个文件读进内存，超过 `maxBytes` 报错，边读边报进度。

`SshBackend` 加一个可选项 `editorWindow`（类型是 `WindowLink`，连接管理器窗口也用它）：`open()` 打开或切到编辑窗口，`post(msg)` / `listen(handler)` 收发上面的消息。没有这项的平台（网页端）用主窗口里的浮动窗口。

- 内核：`Sftp::stat`、`Sftp::read_file`（先 stat，超过上限直接报错，不开始读）。
- 桌面端命令：`sftp_stat`、`sftp_read`（直接返回原始字节，不转 JSON 数组）、`editor_window_open`、`editor_set_dirty`、`editor_quit`（在 `apps/desktop/src-tauri/src/windows.rs`）。消息走 Tauri 事件 `editor-msg`，用 `emitTo` 发给对方窗口。
- 编辑窗口由 Rust 建，前端不需要“建窗口”的权限；`capabilities/editor.json` 给编辑窗口 `core:default`、拖动窗口、关闭窗口的权限。
- WASM：`stat`、`readFile`。

### 放弃的方案

- **编辑窗口自己读写文件**（用会话编号直接调 Rust）：主窗口关掉后编辑器还能存，但重连后会话编号会变、传输列表看不到保存，而且网页端做不到。
- **主窗口里的浮动窗口**（设计稿原来的推荐）：所有者选了单独窗口，网页端保留它当退路。
- **下载到临时文件再用系统里别的编辑器打开**：要监视本机文件变化，各平台不一样，手机上做不到；文件也会落到电脑上，和所有者的要求相反。

## 数据

不存新东西。编辑中的文字只在编辑窗口的内存里，关了就没了（关之前会问）。

## 对其他平台的影响

- 网页端：浮动窗口，读写走同一套 `stat` / `readFile` / `upload`。
- Windows：Tauri 一样能开第二个窗口，`editor-msg` 不用改。
- 手机：以后编辑器可以做成全屏页面，用同一个编辑组件。

## 怎么测

- 内核：`real_server.rs` 里加 `read_file`（正常读、超过上限报错、读目录报错）和 `stat` 的测试。
- 界面：`core` 里判断“能不能当文本打开”、冲突判断、消息往返（用一对内存里的消息通道）写单元测试。
- 网页版 `?mock`：双击 /etc/nginx/nginx.conf，改一行保存，再打开看到改过的内容；双击 /var/log/nginx/access.log 看到“太大”的提示；深色浅色各看一遍。
- 桌面端：`scripts/mac-preview.sh` 截图看编辑窗口；关闭时的询问、拖动请所有者自己试。
